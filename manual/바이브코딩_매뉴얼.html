    코드를 직접 짜지 않고, 클로드 같은 AI에게 원하는 것을 말로 설명해 프로그램·화면·자동화를 만드는 방식입니다. 우리 회사의 실적센터, 생산 현황판, 복지용구사업소 운영판도 이렇게 만들었습니다.

    클로드는 신입 개발자, 나는 감독

    클로드가 하는 일내가 하는 일
    코드 짜기, 파일 읽기, 계산, 화면 만들기, 프로그램 설치, 오류 고치기무엇이 필요한지 정하기, 계획 승인, 결과 확인(숫자 대조), 틀린 곳 짚기, 공개·삭제·결제 허락

    감독이 하는 말 세 가지

    1. 원하는 걸 분명히 — "누가, 무엇을, 어떤 모양으로, 어떻게 확인"
    2. 결과를 직접 보고 — 화면을 열고, 숫자를 원본과 맞춰 봄
    3. 틀린 곳을 구체적으로 — "4번째 줄이 원본보다 36,000원 적어"

    원칙 1 · 바로 만들게 하지 말고 계획부터

    계획을 보면 클로드가 내 말을 제대로 알아들었는지 미리 알 수 있습니다. 잘못 알아들었다면 이때 고치는 게 가장 쌉니다.

    바로 만들지 말고 먼저 계획부터 보여 줘. 단계별로 무엇을 할지, 어떤 파일을 읽고 만들지, 다 됐는지 어떻게 확인할지 적어 줘.

    더 잘하는 법

    • 계획 모드: 클로드 코드에서 Shift+Tab을 눌러 계획 모드로 바꾸면, 파일을 고치지 않고 계획만 세웁니다.
    • 인터뷰 받기: 큰 일이면 "명세를 쓸 수 있을 때까지 나에게 질문해 줘. 끝나면 SPEC.md로 정리해 줘"라고 시킵니다. 그다음 새 대화에서 그 파일로 만들게 합니다.

    원칙 2 · 구체적으로 말하기

    나쁜 지시"보기 좋게 만들어 줘"
    "실적 화면 하나 만들어"
    "이거 고쳐 줘"
    좋은 지시"팀장님이 아침 회의 때 보는 화면이야. 채널별 어제 매출과 지난주 같은 요일을 나란히, 한 화면에 큰 글씨로. 다 되면 원본 엑셀 합계와 같은지 확인해 줘."

    클로드가 볼 수 없는 것을 알려 주기

    • 파일: 위치를 정확히. 클로드 코드에서는 @파일이름으로 파일을 바로 넘길 수 있습니다.
    • 화면: 말로 설명하기 어려우면 캡처해서 붙여 넣기. 그림 한 장이 긴 설명보다 정확합니다.
    • 회사 사정: "반품은 합계에서 뺀다", "쿠팡 로켓은 따로 본다"처럼 코드에 없는 규칙.

    원칙 3 · 한 번에 다 시키지 말고 작게 쪼개서

    큰 일을 통째로 시키면 어디서 틀렸는지 찾기 어렵습니다. 한 단계가 끝나면 확인하고 다음으로 갑니다.

    1엑셀 1개 읽기읽은 줄 수 확인
    2합계 계산원본 합계와 대조
    3화면 그리기눈으로 확인
    4메일 보내기나에게 먼저 시험
    이번엔 1단계만 해 줘. 엑셀 1개를 읽고 몇 줄 읽었는지, 합계가 얼마인지만 보여 줘. 내가 확인하면 다음 단계로 가자.

    원칙 4 · 결과는 눈으로, 숫자는 원본과 대조

    클로드가 "다 됐습니다"라고 해도 내가 확인하기 전까지는 미완성입니다. 한 줄이라도 원본과 다르면 완성이 아닙니다.

    확인 방법

    • 원본 엑셀 합계 ↔ 화면 합계를 줄마다 비교 (대조표를 만들어 달라고 해도 됨)
    • 화면은 직접 열어 보고, 휴대폰에서도 열어 보기
    • "검사 결과를 명령과 출력으로 보여 줘" — 말이 아니라 증거를 받기

    틀렸을 때 말하는 법

    ✕"이상해. 다시 해 줘"
    ○"4번째 줄 복지몰 합계가 원본보다 36,000원 적어. 반품을 두 번 뺀 것 같아. 확인하고 고쳐 줘"

    몇 번째 줄, 얼마나 다른지, 짐작 가는 원인까지 말하면 한 번에 고쳐집니다.

    원칙 5 · 잘 될 때마다 저장점

    깃(Git)은 게임 저장과 같습니다. 다음 단계에서 망가져도 잘 되던 때로 바로 돌아갈 수 있습니다.

    이럴 때클로드에게 이렇게
    한 단계가 잘 끝났을 때"지금 상태 커밋해 줘. 메시지는 '합계 계산 완성'으로."
    처음 시작하는 폴더"이 폴더를 깃으로 관리하게 해 줘. 비밀 파일(.env)은 빼고."
    망가졌을 때"마지막 커밋 상태로 되돌려 줘. 되돌리기 전에 무엇이 사라지는지 먼저 보여 줘."
    방금 대화만 되돌릴 때클로드 코드의 /rewind 또는 Esc 두 번 (깃을 대신하지는 않음)

    원칙 6 · 고친 것은 규칙 파일에, 대화는 짧게

    CLAUDE.md는 클로드가 일을 시작할 때마다 먼저 읽는 규칙 파일입니다. 고친 것을 적어 두면 같은 실수를 두 번 하지 않습니다.

    # 우리 팀 작업 규칙
- 반품은 합계에서 한 번만 뺀다
- 화면 글씨는 16px 이상, 한 화면에
- 비밀번호·키는 .env 에만
- 끝나면 원본 합계와 대조하고 결과를 보여 준다
    • "오늘 고친 거 규칙에 저장해 줘" 한 마디면 클로드가 적습니다.
    • 짧게 유지: 코드를 읽어서 알 수 있는 건 빼고, 회사 사정·함정·확인 방법만.
    • 대화가 길어지면 클로드도 앞 내용을 헷갈립니다. 일이 바뀌면 /clear로 비우고 새로 시작. 같은 걸 두 번 고쳤는데도 틀리면 /clear 후 더 나은 지시로 다시.

    하나 · 파일과 폴더의 경로

    경로는 파일의 주소입니다. 클로드에게 "그 파일"이 아니라 주소로 말해야 정확합니다.

    C:\Users\직원\문서\실적합계\쿠팡.xlsx
    • 파일 탐색기에서 파일을 Shift+오른쪽 클릭 → 경로로 복사
    • 폴더 안에서 클로드를 열면 그 폴더가 '작업 폴더'가 됩니다. 이름이 겹치지 않게 폴더를 나눠 쓰기
    • 확장자(.xlsx .csv .py .html)는 파일의 종류. 탐색기 보기 → 파일 확장명 켜기

    둘 · 터미널 (글자로 명령하는 창)

    윈도우에서는 PowerShell. 클로드 코드는 이 창 안에서 일합니다. 명령을 외울 필요는 없고, 아래 다섯 개만 알면 됩니다.

    명령뜻
    cd 폴더이름폴더로 들어가기 (cd .. 한 칸 위로)
    ls지금 폴더의 파일 보기
    claude지금 폴더에서 클로드 코드 시작
    Ctrl+C돌고 있는 일 멈추기
    위 화살표방금 쓴 명령 다시 불러오기

    셋 · 웹 프로그램은 3층 + 창구

    이름뜻우리 회사 예
    화면 (프런트엔드)눈에 보이고 누르는 부분실적센터 웹 화면
    서버 (백엔드)뒤에서 계산·저장·로그인 처리매일 06:00 자료를 모으는 프로그램
    데이터베이스자료를 쌓아 두는 곳생산 계획·자금 기록
    API프로그램끼리 자료를 주고받는 공식 창구네이버 광고 API, 쿠팡 판매자 API

    자료를 모을 때 순서: 공식 API 먼저 → 없으면 엑셀 내려받기 자동화 → 마지막으로 브라우저 자동 조작.

    넷 · 비밀값은 .env 파일에만

    API_KEY=여기에_키
SITE_PASSWORD=여기에_비밀번호
    • 비밀번호·API 키는 .env 파일에만 적고, 채팅창이나 코드에 직접 쓰지 않습니다.
    • .env는 깃·공유 폴더·인터넷에 올라가지 않게 빼 둡니다(.gitignore). 클로드에게 "비밀 파일은 깃에서 빼 줘"라고 하면 됩니다.
    • 키가 밖으로 나간 것 같으면 바로 그 사이트에서 키를 새로 바꿉니다.

    다섯 · 배포 = 인터넷 주소에 올리기

    내 컴퓨터에서만 보이던 화면(localhost)을 인터넷 주소에 올려 다른 사람도 보게 하는 일입니다. 회사는 주로 Vercel을 씁니다.

    • 고친 뒤에는 같은 주소에 다시 올립니다. 주소가 바뀌면 직원들이 헷갈립니다.
    • 로그인이 없는 주소는 누구나 볼 수 있습니다. 회사 숫자·고객 정보가 있는 화면은 로그인부터 붙입니다.
    • 데이터베이스를 쓰면 권한 설정(누가 읽고 쓸 수 있나)을 반드시 확인합니다 — 안전 수칙의 사고 사례 참고.

    여섯 · 오류 메시지는 고장 난 곳을 알려 주는 지도

    1. 빨간 글씨를 통째로 복사 (앞뒤 몇 줄 포함)
    2. 클로드에게 붙여 넣고 "원인 찾아서 고쳐 줘"
    3. 고친 뒤 "왜 났는지 한 줄로 설명해 줘" — 다음에 같은 오류를 알아보는 눈이 생깁니다
    자주 보는 말뜻
    not found · No such file파일·명령을 못 찾음 → 경로·설치 확인
    401 · 403로그인·권한 문제 → 키·비밀번호·세션 확인
    404주소가 틀림
    500서버 쪽 고장
    SyntaxError코드 문법 오류 → 클로드에게 고치게

    꼭 지킬 7가지

    1. 비밀번호·키는 .env에만. 채팅창·코드·공유 폴더에 쓰지 않기
    2. 고객 개인정보 파일은 클로드에게 올리지도, 보내지도 않기. 필요하면 이름·전화를 지운 견본으로
    3. 지우기·덮어쓰기·외부 공개·결제는 클로드가 먼저 묻게 하고, 직접 확인한 뒤 허락
    4. 작업 전 복사본. 원본 엑셀·폴더는 복사해 두고 복사본으로 작업
    5. 시험은 시험 자료로. 실제 판매·고객 자료로 처음부터 돌리지 않기
    6. 자동 실행은 결과 확인까지. 작업 스케줄러는 '마지막 실행 결과 0'인지 확인. 0이 아니면 조용히 실패 중
    7. 로그인 1곳만 되는 사이트는 자동화가 내 접속을 끊을 수 있으니 조심

    단계별 과제와 배울 것

    단계과제 (하나만 끝까지)이 단계에서 배울 것다 했다는 증거
    1 입문채널별 엑셀 3개 합쳐 합계표 만들기경로, 터미널, 4칸 지시문, 원본 대조원본과 같은 합계표
    2 실무내 업무 현황판(HTML 한 화면) 만들기계획 모드, 작게 쪼개기, 깃 커밋·되돌리기, CLAUDE.md커밋 5개 이상 + 규칙 3줄

    4 설계팀이 함께 쓰는 입력·승인 화면데이터베이스, 로그인·권한, 시험(테스트), 코드 검토 받기동료 2명이 실제로 씀

    빨리 느는 습관 3가지

    1. 만든 코드를 설명해 달라고 하기 — "방금 만든 걸 쉬운 말로, 파일마다 한 줄씩 설명해 줘"
    2. 오류 문구 직접 읽어 보기 — 붙여 넣기 전에 한 번 읽고 짐작해 보기
    3. 매일 작은 것 하나 — 큰 프로젝트 하나보다 작은 완성 열 개가 빨리 늡니다
